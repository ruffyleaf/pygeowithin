pygeowithin

Draw a polygon over a map and get back every point that falls inside it. A small Python + MongoDB geospatial toolkit: load your points once, then query them by an area and export the matches as GeoJSON to plot.

Python 2 scripts MongoDB 2dsphere GeoJSON in / out github.com/ruffyleaf/pygeowithin

01What it does

pygeowithin answers one question: “which of my points are inside this shape?” It leans on MongoDB's geospatial index to do the heavy lifting, so the workflow has two phases:

  • Load your set of points into a MongoDB collection with a 2dsphere index (once).
  • Query by a polygon — supplied either as a list of lat/lon corners or as a GeoJSON polygon — and receive a GeoJSON FeatureCollection of every point inside it.

The output drops straight into geojson.io (or any map tool) so you can see the matched points in context.

Why Mongo? A $geoWithin query against a 2dsphere index is a true geodesic “point-in-polygon” test — it understands that the Earth is curved and handles large areas correctly, instead of you computing it row-by-row in Python.

02Prerequisites

You'll need MongoDB running locally, the Python driver, and a Python 2 interpreter (the scripts use Python 2 syntax — see Gotchas).

# Install the MongoDB Python driver (Python 2)
pip install pymongo

# Make sure a local MongoDB server is reachable at mongodb://localhost
mongod            # start it (or: brew services start mongodb-community)

# Create the database/collection with a geospatial index (in the mongo shell)
mongo
> use grid
> db.points.createIndex({ "loc": "2dsphere" })

The index on loc is what makes the $geoWithin query work — create it before running any query script. The scripts always talk to database grid, collection points.

03How points are stored

Each document in grid.points looks like this — a GeoJSON Point in loc, plus display properties carried into the output:

{
    "code": "1",
    "title": "S1.107",
    "loc": { "type": "Point", "coordinates": [103.6086259, 1.408475502] },
    "description": "grid",
    "marker-color": "#000000",
    "marker-symbol": "circle"
}
Coordinate order: MongoDB stores [longitude, latitude] — lon first. This is the reverse of how most people write a location, and it's the single most common source of “my query returns nothing” bugs. Keep it in mind everywhere in this project.

04Loading points into Mongo

uploadtoMongo.py reads a CSV of points and inserts them as documents. The expected CSV columns are code, title, lat, lon, ….

# speedcam_map.csv is hardcoded as the source file inside the script
python uploadtoMongo.py

For each row it maps the leading code to a description and a map marker style, then stores the location (flipping to [lon, lat]) in loc:

for row in geodata:
    code  = row[0]
    title = row[1]
    lat   = float(row[2])
    lon   = float(row[3])

    if   row[0] == '1': description, markercolor, markersymbol = "grid",         '#000000', 'circle'
    elif row[0] == '2': description, markercolor, markersymbol = "accident",     '#ee2a2a', 'danger'
    elif row[0] == '3': description, markercolor, markersymbol = 'lamp post',    '#ffe800', 'marker-stroked'
    elif row[0] == '4': description, markercolor, markersymbol = 'traffic light','#009647', 'car'
    elif row[0] == '5': description, markercolor, markersymbol = 'road hump',    '#808080', 'roadblock'
    else:               description, markercolor, markersymbol = 'N/A',          '#ffffff', 'theatre'

    points.insert({
        'code': code,
        'title': title,
        'loc': {'type': 'Point', 'coordinates': [lon, lat]},   # lon, lat!
        'description': description,
        'marker-color': markercolor,
        'marker-symbol': markersymbol,
    })

Change speedcam_map.csv (and the code→style mapping) to match your own dataset. The header line is skipped with geodata.next().

05Defining your area

There are two ways to describe the polygon you want to query, and a matching script for each:

A · Lat/lon corners

A simple CSV listing the polygon's corners (one lat, lon per line, like coord.in). Run with getPointsInGrid.py.

B · GeoJSON polygon

A .geojson file containing a Polygon — typically drawn and exported from geojson.io. Faster to set up. Run with getPointsInPolygon.py.

The query itself is identical in both scripts; only how the polygon is assembled differs.

06Query by lat/lon corners

getPointsInGrid.py <infile> <outfile>

The input file is plain lat, lon pairs — for example the shipped coord.in, a rectangle over central Singapore:

1.314250, 103.800871
1.312684, 103.806256
1.307578, 103.806321
1.307685, 103.801214

Run it:

python getPointsInGrid.py coord.in outfile.geojson

Under the hood the script flips each lat, lon row to [lon, lat], appends the first corner to close the ring, then runs the geospatial query:

coordinates = []
for c in coords:                       # each row: "lat, lon"
    x = [float(c[1]), float(c[0])]     # store as [lon, lat]
    coordinates.append(x)

coordinates.append(coordinates[0])     # close the polygon ring

results = points.find({
    "loc": {
        "$geoWithin": {
            "$geometry": {
                "type": "Polygon",
                "coordinates": [coordinates]
            }
        }
    }
})

It prints the assembled [lon,lat] corners to the console first, so you can sanity-check the shape before trusting the results.

07Query by GeoJSON polygon

getPointsInPolygon.py <infile.geojson> <outfile.geojson>

If you already have a polygon as GeoJSON — for instance drawn on geojson.io and saved — this is the faster route because there's no corner list to type out. The input is a FeatureCollection whose first feature is a Polygon:

{
    "type": "FeatureCollection",
    "features": [
        {
            "type": "Feature",
            "geometry": {
                "type": "Polygon",
                "coordinates": [[
                    [103.800871, 1.314250],
                    [103.806256, 1.312684],
                    [103.806321, 1.307578],
                    [103.801214, 1.307685],
                    [103.800871, 1.314250]
                ]]
            },
            "properties": {}
        }
    ]
}

Run it:

python getPointsInPolygon.py area.geojson outfile.geojson

The script lifts the polygon straight out of the first feature and feeds it to the same $geoWithin query:

polygon = json.load(open(infile, 'rb'))

results = points.find({
    "loc": {
        "$geoWithin": {
            "$geometry": {
                "type":        polygon['features'][0]['geometry']['type'],
                "coordinates": polygon['features'][0]['geometry']['coordinates']
            }
        }
    }
})

Note it only ever reads features[0], so keep the polygon you care about as the first feature in the file.

08Output & plotting

Both scripts convert the matched documents into a GeoJSON FeatureCollection and write it to your outfile:

gj = {"type": "FeatureCollection", "features": []}
for r in results:
    gj["features"].append({
        "type": "Feature",
        "geometry": r['loc'],
        "properties": {
            "title": r['title'],
            "description": r['description'],
            "marker-color": r['marker-color'],
            "marker-symbol": r['marker-symbol']
        }
    })

open(outfile, "wb").write(json.dumps(gj, sort_keys=True, indent=4, separators=(',', ': ')))

A single output feature looks like this (this is the shape you'll see in the sample grid.geojson):

{
    "geometry": { "coordinates": ["103.6086259", "1.408475502"], "type": "Point" },
    "properties": { "description": "grid", "marker-color": "#000000", "title": "S1.107" },
    "type": "Feature"
}

Open geojson.io, use Open file → GeoJSON, and your matched points appear on the map with the stored colors and marker symbols.

09Worked example

Putting it together with the files in the repo:

# 1. Load points (one-time), then index them
python uploadtoMongo.py
mongo --eval 'db.getSiblingDB("grid").points.createIndex({loc:"2dsphere"})'

# 2. Find every point inside the rectangle described by coord.in
python getPointsInGrid.py coord.in outfile.geojson

# 3. Inspect the result
open https://geojson.io   # then Open file → outfile.geojson
  1. Confirm the console line Check the coordinates [lon,lat] : shows the corners you expect.
  2. The more features in your collection, the more $geoWithin saves you versus scanning rows in Python — the index does the work.

10Gotchas & notes

  • Python 2. getPointsInGrid.py uses a print statement and uploadtoMongo.py uses geodata.next(); open files in 'rb'. On Python 3 these raise. A quick port: print(...), next(geodata), and open in text mode. The logic itself is unchanged.
  • Index first. No 2dsphere index on loc → the $geoWithin query returns nothing or errors.
  • Lon, lat — always. Input CSV is lat, lon; storage and GeoJSON are lon, lat. The scripts convert, but hand-editing coordinates is where things go wrong.
  • Close the ring. For the corner file the script auto-appends the first point; a GeoJSON Polygon you supply must already be closed (first coordinate = last).
  • Only the first feature of the input GeoJSON polygon is used.
  • Hardcoded paths & names: the Mongo URI (mongodb://localhost), db/collection (grid/points), and the source CSV (speedcam_map.csv) are baked in — adjust for your setup.
  • Marker properties (marker-color, marker-symbol) are geojson.io's simplestyle conventions, so they render automatically there.
